Shipped since the plan

  • Phase 4 word timings, behind the word-timings setting (default off).
  • Voices listed from the server; the Librarian profile becomes the default voice once the server lists it, unless the listener has picked one.
  • Durable background preparation on two machines: the Mac mini first, the local container as overflow only for voices synced byte for byte from the Mac.
  • A shared catalogue of prepared readings across devices; a device uploads clips it already holds so others needn’t render them.
  • Breathy-noise retakes: a take with under 20 % voiced speech is asked again up to 2 times, in the browser and in preparation.
  • Busy (429) retries wait at most 5 s; background preparation pauses until live speech has been quiet for 15 s.
  • The iOS app has no proxy: it reads with the iPhone’s voice, or with a speech server and key set in Settings.

Goal

ReadAloud keeps its current playback engine, cache and fallback chain. VoiceStudio is reached through the same-origin /api/vs/v1/audio/speech proxy, so the browser never talks to it directly and never holds its key.

In scope

  • Run VoiceStudio locally in Docker on the CPU, with KittenTTS as the first engine.
  • A proxy that adds the API key and satisfies VoiceStudio's origin and host checks.
  • A provider adapter for its OpenAI-style speech endpoint.
  • Voices listed from the server instead of the hard-coded eight (the fallback list now has 15).
  • Tests that run without VoiceStudio, plus a tagged live suite.

Original scope exclusions

  • Voice cloning UI. The server's own app covers it; ReadAloud only lists resulting profiles.
  • Dubbing, transcription, dictation and the mobile apps.
  • GPU engines. OmniVoice wants about 6 GB of graphics memory and its weights are non-commercial. Reversed: OmniVoice on the Mac mini’s GPU is now the main engine.
  • Forking VoiceStudio. Calling it over HTTP keeps ReadAloud's licence independent of its AGPL terms.

Why this shape

The adapter is small because ReadAloud already synthesized one sentence per request (now one passage of up to ~60 words), prefetched upcoming passages and cached audio in IndexedDB. The only missing piece on the server side was word timings, which stay estimated unless the word-timings setting is on.

Where each piece runs now

Hover or tap a box. Tailscale and Traefik route to the web server. VoiceStudio can run on the Mac or in kind; AWS hosts only the web app. Persistent data stays with the web host.

What VoiceStudio gives us, and what it doesn't

NeedVoiceStudioPlan

Voice listYesGET /v1/audio/voices, plus /profiles for profile kinds and /engines for the active engine.
Word timingsNoSpeech endpoint is audio only. Phase 4 derives timings from the transcription endpoint.
Browser callsGatedNeeds bearer key, listed origin and known host. Proxy handles all three.
StreamingYesChunked audio or a WebSocket. Not needed: sentences are short and prefetched.
Speed controlServer-sideAlways request 1×. The audio element's playback rate handles speed, so cached clips work at any speed.
